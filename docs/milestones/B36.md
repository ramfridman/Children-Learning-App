picture gets a hands-on item (drag, give, sort, build) or a symbol item; a symbol-only skill gets a picture; a hands-on

(likely candidates: COL-B-01 mixing, CS-B-04 fixing a program), it gets an authored story item, or it goes to the owner
as a template proposal. It is never left out without a word.

## 6. The owner signs (part J), exact PowerShell steps

Do this only when the orchestrator says "the pack is ready to sign" and gives you the commit id.

1. Open PowerShell.
2. `cd D:\nitznutz-next`
3. `git status` and check that it says `On branch next-pack` and `nothing to commit, working tree clean`.
4. `git log -1 --oneline` and check that the id is the one the orchestrator gave you.
5. `Test-Path "$env:USERPROFILE\nitznutz-secrets\pack-signing.key"` must print `True`. If it prints `False`, open the
   1Password note "Nitznutz pack signing key" and save its text to that path with Notepad. Never paste the key into the chat.
6. `cd D:\nitznutz-next\app`
7. `dart run tool/pack_builder.dart build ..\content\starter --out assets\packs`
   It prints `Built assets\packs\starter-0.11.0.nnpack: <bytes> bytes, manifest sha256 <hash>`. Lines that start with
   `WARNING:` are expected (the orchestrator lists them in advance).
8. `dart run tool/pack_builder.dart verify assets\packs\starter-0.11.0.nnpack` must end without an error.
9. Send the orchestrator the size and the manifest sha256 from step 7 (they are not secret). Nothing else.

## 8. Risks

| Risk | What we do |
|---|---|
| The branch drifts from `main` and generated files conflict (as on 2026-11-01) | merge `main` after each part and regenerate generated files instead of hand-merging; only source files get resolved by hand |
| The branch is red by design until the owner signs (`starter_pack_test` "built from the sources"), which can hide a new red | part G runs the whole suite against a throw-away-signed copy, so the known red is the only one |
| The owner's reading time (about 1,700 rows) delays the pack | the sample-and-rule review of decision 7; the editor flags the rows that truly need him |
| More tagged answers change what the engine diagnoses and re-teaches | re-run the M3 simulator on the new pack; QA checks that every tag has a line and a re-teach |
| A skill has no fitting template for its second way | an authored story item, or a template proposal to the owner; never silently skipped |
| A hint line stops matching its picture when a picture changes | QA item 5; pictures and lines change only together |
| Existing ids renumbered would break the children's history | new items are only appended (as in B-15); a test already guards the existing ids |
| The bundled pack is newer than the server index, so the tutor does not know the new items | publish 0.11.0 together with the app that bundles it (part M); until then the tutor falls back to RuleTutor |
| The signing key is not on the PC | step 5 of section 6 (1Password); the key never goes into the chat or the repo |
| Paid voice | Claude never runs a paid command; the owner runs B-45 in his own terminal and types the count |
