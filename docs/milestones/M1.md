# M1 — App shell and design system: milestone plan

**Status:** Draft, waiting for the owner's OK. Nothing in this plan is coded yet.
**Branch:** `m1-app-shell` (from `main`, after M0 was merged on 2026-10-26)
**Source of truth:** `docs/PLAN.md` › Build plan (M1), Security architecture (local data, PIN, roles), `docs/design-spec.md` §5 to §9 and §13, and `design/tokens.json`. Where this file and PLAN.md differ, PLAN.md wins and the difference is listed in section 3.

## 1. Goal and "done when"

From PLAN.md, unchanged:

- The Flutter app reads `tokens.json`, is right-to-left, uses Heebo and Secular One, and has phone and tablet layouts.
- Child and parent areas are separate, with a parent gate and a PIN.
- Local data is in an encrypted database.
- **Done when:** screenshots match boards 10 and 13; PIN lock-outs work; the database file can't be opened without the key.

M1 builds the frame the later milestones sit in. It does not build activities (M2), the learning engine (M3), characters or voice (M4 onward), or the real parent dashboard (M7).

**What changes because of how your family uses the app.** Your children use your phone, your wife's phone and a tablet, so almost every device will be enrolled as a `parent` device and shared. On such a device the parent gate and the PIN are the only barrier between a child and the parent area, so they get the most care in this milestone: the PIN is mandatory before any child profile exists, the parent area locks after 5 idle minutes or when the app goes to the background, and Android blocks screenshots there. (The `child` role from M0 stays available for a kid-only device later.)

## 2. How we verify

I now have Flutter, Android SDK and your phone on this machine, so I run the analyzer, formatter, tests and golden screenshots myself after every step and push only when they are green; CI stays the referee. Everything that needs your eyes (do the screenshots look like the boards, is the Hebrew right) is a numbered step for you with side-by-side pictures.

## 4. Tasks, in order

Each task ends with a check. "Who" is me unless it says otherwise.

### Phase A — Approvals (you)

- **A1.** Approve the packages in section 6 and the font download (E6).
- **A2.** When you are at the computer: `git pull`, then `npx supabase functions deploy --use-api` (it puts the audited ECDSA library from M0 live), and send me the two spend-limit screenshots.

### Phase B — Design system

- **B1.** A small Dart tool, `tools/gen_tokens.dart`, turns `design/tokens.json` into `app/lib/design/tokens.g.dart`. A test fails if the generated file is out of date. *Check:* changing a value in the JSON without regenerating fails CI.
- **B2.** `app/lib/design/`: colours (child and parent palettes), type styles (Secular One titles; Heebo text, **line height 1.7 for any text with nikud**, real weights, never synthetic bold), spacing, radii, elevation, touch-target sizes per band, motion durations.
- **B3.** Components from board 05: primary button, round icon button, caption pill, answer tile, progress trail, speech bubble, parent control (44 pt, grey and night, visibly "adult"). Each has a widget test and a golden.
- **B4.** Layout: size classes (phone, SE, tablet landscape and portrait), safe areas, start and end instead of left and right, "maths is always left to right in an isolated tile" helper (used by M2 onward), and a test that renders a number line and a clock in a Hebrew context and checks they are not mirrored.
- **B5.** Fonts bundled; a test fails if any other font family appears in the code or in `pubspec.yaml`.

### Phase C — Encrypted local data

- **C1.** `app/lib/data/`: Drift database `AppDatabase` with a random 256-bit key made on first run, stored in secure storage (Android Keystore, StrongBox where present). Tables for M1: `profile` (first name as parent-reviewed spelling, avatar id, address form, age band), `app_setting`, and `local_event` (for the local record of gate and PIN events). Migration skeleton with a schema-version test.
- **C2.** *Check, the plan's acceptance test:* a test copies the database file and (a) opens it with plain SQLite and gets "not a database", (b) opens it with a wrong key and gets the same, (c) finds no readable text from a known profile name in the raw bytes, (d) opens with the right key and reads the row. A second test checks that the key never appears in the file system outside secure storage.
- **C3.** A fresh install creates a new key and an empty database; "forget this phone" deletes the key and the file.

### Phase D — PIN, gate and parent-area lock

- **D1.** `app/lib/security/pin_service.dart`: Argon2id hash with a random salt, parameters stored with the hash so they can be raised later; constant-time comparison; lock-out schedule and counter in secure storage; injected clock for tests. Rolling the phone's clock back must not shorten a lock-out (the lock stores both wall-clock and monotonic elapsed time and uses the longer remaining time).
- **D2.** `app/lib/security/parent_gate.dart`: the arithmetic gate with Hebrew number words, shuffled keypad, and the cool-down rules from E4.
- **D3.** `app/lib/security/parent_session.dart`: unlocked state, 5-minute idle timer, lock on background (app lifecycle), and the Android `FLAG_SECURE` channel.
- **D4.** Tests: every row of the lock-out table, counter survives an app restart (new service instance over the same fake secure store), clock rollback, wrong PIN length, gate cool-down, idle lock with a fake clock, lifecycle lock.

### Phase E — Screens and navigation

- **E1.** Navigation with plain Flutter `Navigator` and named routes (no router package). Child code lives in `app/lib/child/` and parent code in `app/lib/parent/`; **a test fails if anything in `child/` imports `parent/`**.
- **E2.** Parent setup (first launch, board 11): welcome, email-code sign-in, enrol this device, set the PIN, create the first child profile (name, avatar, how Nitzi addresses the child), voice choices left off. Adult UI, Hebrew without nikud.
- **E3.** Profile picker for siblings (board 11), "add child" leading to the gate (kids cannot create or delete profiles).
- **E4.** Child Home (boards 10 and 12): a static island map with placeholder content, the "Parents" button at the start corner opening the gate, the profile avatar at the end corner, Nitzi and a speech bubble.
- **E5.** Activity shell (board 13): top controls, progress trail, stage, caption pill, answer tiles and mic button as inert visuals; no logic (M2).
- **E6.** Parent area stub: devices list with revoke (uses the M0 calls), change PIN, add profile, version (long press opens the dev harness in the `dev` flavour).
- **E7.** All new Hebrew strings in one catalogue, each marked `"review": "needs-editor"`. Child-facing strings carry full nikud and are marked for review; nothing is generated at runtime.

### Phase F — Proof and polish

- **F1.** Golden screenshots in right-to-left with the real fonts: phone 852×393, SE 667×375, tablet 1180×820 and 820×1180, for Home, activity shell, gate, PIN entry, parent area. I send you side-by-side pictures next to boards 10, 12, 13, 22 and 23.
- **F2.** On your Samsung: install the new build and run the real checks (section 5, last rows). Reduce-motion and large-text settings checked once.

## 9. Risks and unknowns

- **Argon2id speed on a phone.** Pure Dart can be slow. Mitigation: measure on your Samsung first and choose parameters that give about 0.5 s; if no pure Dart library is fast enough, I come back to you with a native option.
- **The encrypted SQLite build step downloads a prebuilt library.** Mitigation: the build checks its hash; the version is pinned; the option to mirror the file ourselves is documented by the package.
- **Matching the boards.** The boards use final artwork; M1 uses simple stand-ins for islands. The score is layout and look and feel, not artwork.
- **Hebrew number words for the gate** are drafted by me and marked `needs-editor`.
- **Phone clock rollback** cannot be fully prevented on a device the child can change settings on; the PIN lock uses both clocks and the gate is a speed bump (the design spec says so).

**Differences from the plan above**

- **Fonts** come from the official `google/fonts` repository as TTF, not from `@fontsource` (which ships only web formats Flutter cannot load). Same families, same licence (SIL OFL), files and licence texts are in `app/assets/fonts/`.
- **Token tool** is `app/tool/gen_tokens.dart` (inside the Flutter package so a test can import it), not `tools/`.
- **Argon2id library:** `hashlib` 2.4.2, chosen by measurement (same output as `cryptography`, about 2.5 times faster).
- **Extra Android bridge** (`PlatformChannel.kt`): the no-backup folder, `FLAG_SECURE`, and a monotonic clock for lock-outs.
- **Tablet home** shows all seven lands like board 22 (placeholder names for the four not in the phone view); phones show three lands like board 10.
- **Gate and PIN screens** use a side-by-side layout on a phone held sideways, so nothing needs scrolling (found when the first run pushed the OK button off the screen).
- **Goldens** are compared with a 1.5 percent tolerance because Windows and Linux anti-alias text slightly differently.
