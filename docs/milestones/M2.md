## 1. Goal and "done when"

From PLAN.md, unchanged:

- JSON schemas and the validator; the pack builder that signs packs; pack install with signature checks; the count-and-tap template with misconception tags.
- **Done when:** the butterflies lesson plays end to end by tap; a pack with one changed byte is refused.

M2 is where lessons stop being code and become **signed data**. A lesson is a set of JSON files and pictures, packed and signed on your computer, checked by the app before a single file of it is read, and played by a template. M2 does not build the learning engine (M3: it only *records* what happened), characters and voice (M4, M5), the tutor (M6), or the download from the internet (the pack is bundled in the app for now).

## 2. How we verify

Everything runs on this PC (Flutter, Dart and the Android toolchain are here), so I run the analyzer, formatter, tests and screenshots after every step and push only when green; CI is the referee. The two acceptance criteria become tests that anyone can read: a scripted child who plays all six steps of the butterflies lesson by tapping, and a test that changes every byte of a real pack, one at a time, and requires the installer to refuse each one.

## 4. Tasks, in order

### Phase A — Approvals and the key (you)

### Phase B — Schemas and the validator

- **B1.** `app/lib/content/schema.dart`: a small schema definition language (object, array, string with pattern and length, integer and number ranges, enum, reference, "no unknown fields") and the validator that runs it, reporting the **path** of every problem (`activities/num.count.a.03.json › answer.options[1].misconception`).
- **B2.** The schemas: `manifest/v1`, `activity/v1` (with the `count_tap`, `tap_answer` and `give_n` parts), `skill/v1`, `misconception/v1`, `lesson/v1`.
- **B3.** `tool/pack_builder.dart schema` writes `content/schemas/*.schema.json` (JSON Schema, draft 2020-12) from the same definitions; a test checks they are current.
- **B4.** Cross-file checks the single-file schemas cannot do: every `skill`, `misconception`, `vo:`, `asset:` and `activity` reference exists in the pack; ids are unique; every misconception tag is in the catalogue; Hebrew lint (niqqud present in Bands A and B, no Latin letters in captions, maths tokens separate).
- **Check:** at least 30 deliberately broken files, each refused with the right path and reason.

### Phase C — The pack builder and the format

- **C1.** `tool/pack_builder.dart keygen | build | verify | inspect | schema`. `build` reads a source folder (`content/starter/`), validates everything, makes the manifest (id, semver, minimum app version, minimum template versions, a SHA-256 and size for every file), writes a **deterministic** zip (sorted names, fixed times, so the same sources always give the same bytes) and signs the manifest bytes with Ed25519.
- **C2.** The pack file is `<id>-<version>.nnpack` and holds `manifest.json`, `manifest.sig` and the files, flat.
- **Check:** building twice gives identical bytes; `verify` accepts a good pack and refuses each broken one.

### Phase D — Installing a pack (the security core)

- **D1.** `app/lib/content/pack_installer.dart`: reads the narrow zip (refusing anything outside P4: unknown methods, flags, extra fields, duplicate or unsafe names such as `..`, `/`, `\`, drive letters, a leading dot, overlong names, and more than 400 files or 64 MB in all), checks the signature against the built-in public key (P5), then every file's hash and size, then the rules below, then installs.
- **D2.** Rules: a pack with an id and version **lower than** the installed one is refused; the same version with different bytes is refused; the same version with the same bytes does nothing; a pack that needs a newer app or template stays **hidden** (installed but not offered) so an old app never crashes.
- **D3.** Files go into a temporary folder and are moved into place in one step, so a crash leaves either the old pack or the new one, never half of one. Packs live in the no-backup folder.
- **D4.** Database version 2 (P10), with a migration test from version 1.
- **Check, the acceptance test:** a real pack is installed; then every byte of it is changed in turn (the zip headers, the manifest, the signature, each activity, each picture) and **every** changed copy is refused, with nothing installed and nothing left in the folder.

### Phase E — The first lesson as data

- **E1.** `content/starter/`: `skills/` and `misconceptions.json` (the counting entries: `M-CNT-DOUBLE`, `M-CNT-SKIP`, `M-CNT-CARD`, `M-CNT-SEQ`), six activities for the butterflies lesson (NUM-A-03/04, warm-up COL-A-02), the lesson file, and the pictures (butterfly in two wing positions, red and yellow flowers, the jar).
- **E2.** The builder builds it into `app/assets/packs/starter-0.1.0.nnpack`, signed with the real key (A2). The app installs it on first start.

### Phase F — The player

- **F1.** `app/lib/play/`: the lesson runner (one activity after another, the trail advances, attempts and hints counted per the activity's `scoring`) and the three templates, drawn in the board frame from M1 (the same positions, sizes and corner radii).
- **F2.** `count_tap`: butterflies tap-to-count, each tapped one lights up and flies to the flower (or glows when it stays), a counter, then the answer tiles. Classifiers from the activity file: the same butterfly tapped twice → `M-CNT-DOUBLE`; choosing n+1 → `M-CNT-DOUBLE`; n−1 → `M-CNT-SKIP`; right count but a different total → `M-CNT-CARD`.

## 9. Risks and unknowns

- **Ed25519 speed on a phone.** Pure Dart verification takes milliseconds on a PC; I measure it on your Samsung. If it were slow, only the install step would feel it (once per pack).
- **A hand-written zip reader.** It accepts a tiny subset on purpose, and the byte-flip test plus a fuzz test (random and truncated files) must never make it crash or install anything.
- **Art.** The butterflies, flowers and jar are simple stand-ins drawn for the pack. They are replaced in M4 and M9; the pack format does not change.
- **Hebrew.** The lesson text comes from curriculum.md, written by an earlier agent and not yet reviewed by a person.
