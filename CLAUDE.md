# CLAUDE.md: standing rules for the Nitznutz repo

Read this file and `PROGRESS.md` at the start of every session. Full specs are in `docs/PLAN.md`; where it differs from `docs/tech.md`, PLAN.md wins.

## What this is
A Hebrew-only learning app for the owner's two children (ages 3–8). Flutter app (iOS via Codemagic and TestFlight, Android installed directly), Supabase Frankfurt backend whose Edge Functions are the only gateway to Claude Haiku 5.5 and ElevenLabs. Built milestone by milestone (M0–M9, PLAN.md › Build plan).

## Workflow
- One milestone at a time. Write a plan in `docs/milestones/Mx.md` and get the owner's OK before coding it. Report against the acceptance criteria at the end.
- Keep `PROGRESS.md` current: status, done, open issues, next step.
- Work on a branch per milestone, and keep `main` green. Run the analyzer, format and tests after every step.
- When the build differs from PLAN.md, update PLAN.md in the same commit.
- Ask the owner only for what only he can do, with exact numbered PowerShell steps.

## The team
- Every piece of work goes through the eight project agents in `.claude/agents/` (the owner's rule, 2026-10-28): infrastructure-engineer, design-director, hebrew-text-editor, voice-and-sound-director, app-developer, qa-engineer, security-engineer, curriculum-expert. Who owns what, the recipes and the hand-off format are in `docs/agents/README.md`; open hand-offs are on `docs/agents/board.md`.

- No change is done until the qa-engineer has verified it; changes to the gateway, auth, crypto, packs, sync or logs also get the security-engineer's review.

## Security rules (never break)
1. No secret in the app, repo, logs or CI output. The app holds only the Supabase URL, the publishable key and the pack-signing public key.
2. Devices send ids, numbers and enums only. Prompts are built on the server from `content_item`, `misconception` and `family_character`.
3. Every function checks four things: it verifies the token itself (JWKS), checks the signed request (canonical format, DER→P1363, nonce, ±60 s), checks the device is active and in the token's family, and checks the role allows the call.
4. The `app` schema is not exposed, and the `anon` and `authenticated` roles have no grants on it. RLS stays on as a second layer.
5. Model output is untrusted. It passes the 10-step validator and is used as plain text only. Any failure falls back to RuleTutor.
6. Use the caps, kill switches and the 3-second tutor budget exactly as specified.
7. Enrolment uses a server challenge, App Attest on iOS and Key Attestation on Android. Emulators enrol only through `dev_device_allowlist` in the dev flavour.
8. Local data is encrypted (key in Keychain or Keystore). The PIN is hashed with Argon2id, and lock-out counters live in secure storage.
9. Network hosts come only from `app/network_hosts.json`, enforced by a test. A new package needs the owner's OK. Lock files are committed, and OSV and `gitleaks` run in CI.

## Child safety
- No child audio is stored or sent. The mic opens only on tap, and only when a parent enabled voice.
- No personal data to any vendor, with one exception the owner chose on 2026-10-25: a child's first name (parent-reviewed spelling) may be sent to ElevenLabs inside a line to be voiced. The model (Anthropic) only ever sees placeholders (`{child}`, `{companion}`). Never a surname, audio, transcript or device id to any vendor.
- No ads, purchases, timers, streaks or guilt in the child's space.
- Unclear speech is never "wrong". The tutor never asks personal questions, and says it is a computer helper when asked.

## Hebrew
- The UI is RTL, but maths renders LTR in isolated tiles; number lines, clocks and robot arrows never mirror.
- Fonts are Heebo and Secular One only. Nikud text gets a line height of 1.7.
- Nikud is never generated by a model at runtime. New Hebrew strings are marked `"review": "needs-editor"`.
- ÷ for division by default (`:` selectable in app settings); = is read as שָׁוֶה; × is read as כָּפוּל.

## Characters and money
- Original characters only. Never draw, bundle or name franchise characters, and never imitate a real person's voice. Personal lite packs are never bundled in a build.
- Show the character count and cost before any paid generation, and wait for OK. Use mocks in tests.
