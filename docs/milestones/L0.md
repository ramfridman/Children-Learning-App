# L0: The category shell (the Languages category: course id, engine additions, settings, gateway)

**Status:** the owner approved the whole Languages frame on 2026-11-03 (`docs/languages/frame.md` §8, Q-F1 to Q-F5, and "there is a lot of work to do even without the voicing, so let's start"). That approval covers this plan. L0 starts now. Branch `languages-foundation`, cut from `languages-team`.

This plan follows `docs/languages/frame.md` (§1.4 to §1.6, §3, §6 L0) and `docs/curriculum.md` §10. Where the build differs, PLAN.md is updated in the same commit.

## 1. Goal and "done when"

The app, the packs, the engine and the gateway know that there is more than one **course** (`core`, `eng`, `heb`, `rus`) and keep them apart, with every engine rule the language courses need in place and tested, **before** any language content or screen exists. Nothing the family uses today changes: the existing starter pack is `core` and behaves exactly as before.

L0 is the *engine core* of the shell. The screens (the island, the three doors, the parent pages) wait for the design-director (section 5).

Acceptance criteria, reported one by one at the end:

1. **F4, the course id.** `course` (`core`, `eng`, `heb`, `rus`) is a field of skills, items, misconception tags, placement, progress, packs and the synced answer. Existing content is `core` with no change. Pack loading supports one signed pack per course (`lang-eng`, `lang-heb`, `lang-rus`); the starter pack stays as it is.
2. **The validator invariants of frame §1.5** are enforced by the pack validator and by the engine's merged catalogue, and each has a test on a small fixture course (not real content): no cross-course prerequisite, evidence, tag, repair, `contradicts` or session; the id prefix agrees with the course; roll-ups have no evidence of their own; the AI tutor is off for language items.
3. **F9, the engine additions of frame §3,** as pure functions with tests: presentation band versus content level; letter-group sub-skills with dotted ids and roll-up mastery; letter bundles; word-set coverage; the per-skill sound-right outcome; course gates; one course per visit; Today's Adventure with each enabled language as a land.
4. **Per-child, per-language settings** (a language on or off, and the switches of frame §1.4): stored on the device, synced inside the family's rules document like the other per-child settings, ids and enums only, checked again on the server, deleted with the child (here and on the server: an additive migration, with a pgTAP case).
5. **`tutor-turn` refuses language-course items** (gateway), and the app never calls the tutor for them (RuleTutor only).
6. **Sync of the course id** is additive: the answer event may carry `course`; the wire patterns widen for the dotted skill ids and the language tag ids; the server and the app agree; a mismatch is dropped on the way in. The course on the wire needs no migration (events are stored as JSON); the settings need one (criterion 4).
7. Analyzer clean, format clean, the whole Flutter suite and the Deno suite green; PLAN.md updated.

## 2. The decisions this plan makes (all follow the frame; none needs a new answer from the owner)

| # | Decision | Why |
|---|---|---|
| D-1 | `course` is **optional in every pack document and defaults to `core`**. A language pack carries `course` on its manifest and every document, and the validator makes them agree. | The starter pack stays byte for byte as it is, so its signature and hashes do not change. |
| D-2 | A language pack's id is exactly `lang-<course>`; a core pack's id never starts with `lang-`. | One signed pack per course (frame §1.5); the gateway can recognise a language pack by its id alone. |
| D-3 | Language skills use the domain `languages`; the id prefix is the course in capitals (`ENG-`, `HEB-`, `RUS-`). Dotted sub-skills `ENG-B-19.G1`, `HEB-B-14.S1`, `RUS-B-24.G10`. | The prefix already matches the course (frame §1.5). |
| D-4 | Language misconception ids are `<course>.<strand>.<slug>` (`eng.ph.dir`), core ones stay `M-XXX-YYY`. | Frame §4.1. |
| D-5 | A **roll-up** is any skill that has dotted children in the catalogue. It is derived, not declared. The catalogue replaces a prerequisite on a roll-up by its children, so the whole engine sees one graph. | "As a prerequisite it means all groups" (frame §3.3.2) with no change to the graph code. |
| D-6 | New optional skill fields: `bundle` (letter bundle id), `setCoverage` (word and letter sets), `soundRight` (`accepts` or `teaches`), `letters` (the skill is letter work). New document kind `gate`. | These are the only data the F9 rules need. The curriculum-expert and the teachers fill them. |
| D-7 | **One course per visit** is enforced twice: the session builder takes a `course` and never serves another course's item, and the app can also build a visit's engine on `Catalog.forCourse`. | Defence in depth for invariant 5. |
| D-8 | Today's Adventure is keyed by an `AdventureLand` (the six trophy lands and one `LanguageLand` per course). A course that is off is not a land. | The rule stays one pure function. |
| D-9 | Per-language settings live in the family's rules document under `languages` (child id, then course), only values that differ from the default. Everything is off or default until a parent changes it; **an existing child sees no language until a parent turns one on**. | Frame §1.4 and Q-F1; "nothing existing changes behaviour". |
| D-10 | The `detail` field of an answer (`exact`, `sound_right`) is **not stored or synced yet**: the pure outcome function returns it, and the storage comes with LS06 (milestone L5). | L0 has no template that writes it. |

## 5. Security items (for the security-engineer's review before merge)

1. **Rule 2, ids and enums only.** The new settings and the `course` field hold enums and booleans; the questionnaire is a closed list of keys and values, checked on the device and again on the server. Nothing free-text.
2. **Rule 5, model output.** The AI tutor is off for every language item at three layers: the activity model (`llmAllowed` is false for a language course), the validator (a language pack with `llmAllowed: true` is refused), and the gateway (`tutor-turn` refuses a pack whose id starts with `lang-`, and an item whose skills carry a language prefix, before any cap is taken or any model is called).
3. **Rule 3, the four checks.** `settings-put` and `sync-push` keep their four checks; the widened patterns are the only change. `tutor-turn` refuses before it reads anything else of the item.
4. **Invariant 9, response codes.** Unchanged and tested: a language answer's `response` still matches the existing id/number pattern; personal turns write no content (LS06, LS10 do that later).
5. **Sync.** A pulled answer whose `course` disagrees with its skill id or its pack id is dropped, so evidence cannot cross courses by a forged or damaged event. The wire patterns widen only for the dotted skill ids and the language tag ids, and the wire-format number is raised with the pinned digest.
6. **Packs.** A language pack is verified exactly like the starter pack (signature first, hashes, then content). The new rules only add refusals. No new package, no new host.
7. **Child safety.** No new input path, no audio, no timer in the child's space. The settings are parent-area only. A language the parent has not turned on does not exist for the child.

## 6. Deploy order

The migration `20261103120000_language_settings.sql` first (it widens a size limit and replaces `app.delete_child` with itself plus one statement), then the functions (`sync-push`, `settings-put`, `tutor-turn`, `content-publish`), then the app that sends `course` and `languages`. Nothing is removed and nothing that fitted before is refused, so an installed build keeps working at every step. L0 deploys nothing.

## 7. What is deferred, and why

- The screens (section 3, second table).
- The storage of the `detail` field (D-10).
- The placement staircase itself (LS13, milestone L4); L0 only gives placement results a course (the placement lesson id and the `assume` check).
- The English rule "at least 6 meaningful encounters of a word before the durable check of its set" (eng syllabus §4.3): the coverage rule is built; the encounter count needs the teacher to say what counts as meaningful.
- Language packs themselves, their templates and any content.
- Wiring the language packs and engines into the app's providers (`world_providers` and `contentProvider` still load the one starter pack): the pure functions take a pack and an engine, and the providers follow with the island and its doors.
- A guard on the push side for an answer whose fields disagree about the course (it cannot arise from the app; the pull side drops it).
- `tutor-prewarm` is not changed: it reads only the items `content-publish` published, and that function now refuses a language pack.
- Set coverage in revisit checks (frame section 3.4, rule 4: "a durable check of a word set uses words not used in its last practice"): the coverage rule and the rotation of new words are built; the check's word choice needs the last practice's words, which the engine does not keep yet.
- The pgTAP files (`10_language_settings.test.sql`, and `07` adjusted to the new limit) were written but not run: this machine has no Docker. CI runs them (`npx supabase test db`).

## 11. QA's defects and the "installed" rule (after QA of L0)
- **The rule (orchestrator decision, from QA's release note).** A language gets a door, an island and a place in Today's Adventure only when it is **on for the child and its signed pack is installed and verified on this device** (`languagesAvailableProvider` in `app/language_providers.dart`: the switches of `languagesProvider` cut with `languagePacksProvider`). If no language qualifies the child sees the 7-land map. Until an ENG-1, HEB-1 or RUS-1 pack is published the island therefore never shows to a child, so L0 can be merged. The parent page still shows the switch; a language that is on without its pack says on its page that the lessons have not arrived yet (`page-no-course`, the existing `langProgressNoCourse`; the progress page says it already). The packs are read once per run; the dev install of `.nnpack` files refreshes them (`dev_home_page.dart`), and the pack download step must invalidate `languagePacksProvider` after an install. Tests: `languages_available_test.dart`; the test rig installs no language pack unless a test sets `AppRig.installedLanguages` (the fixture pack of each course).
- **QA-L0-1 (fixed).** The door does not open its course when its route is no longer current (`ModalRoute.isCurrent`) or the screen is gone; the back pebble always works. Proof in `qa_l0_open_defects_test.dart`, no longer skipped.
- **QA-L0-2 (fixed).** A door's tap area and its Semantics button are one rectangle from the design's section 4.2.1: the bubble, the door and its host, inset by `round(door / 12) - 12` on each side (3, 1, 10, 8), from the bubble's top to the door box's bottom but never into the bottom 24 of the screen (369 on the phone); the bubble is as wide as the rectangle (178, 158, 244, 224). `door_tap_rect_test.dart` checks the design's table on each board with three and two doors: a tap 1 point inside each corner opens that door, 1 point outside each side opens none, and the friend, the grass, the sea and the space between two doors open none; the seven door goldens were drawn again for the design-director's art (QA-L0-3).
- **QA-L0-4 (fixed).** The map waits for the language settings and the installed packs (`languagesReadyProvider`, `CalmLoading` as for the friend and the guide), so a child with a language on never sees one frame of the 7-land map.
- **QA-L0-6 (for L3).** `areaLangVoiceHelp` ("the voice is downloaded to this phone ...") mentions a download that L0 does not do: the voice switch only stores the choice. The text is left as it is; the L3 step that adds the recogniser download makes it true.
