## 1. Goal and "done when"

A language with its voice switch on can listen to a child say one word and answer *confident* or *unsure*, never wrong, from a recogniser that sits on the phone; with the switch off, or with no model, the same screen runs as echo with an "I said it" tap. Nothing is recorded, stored, sent or shown as text. Each language's say-it ships only after its release gate passes.

Acceptance criteria, reported one by one at the end:

1. **The spike** (section 7) answers with numbers: is a confidence available in `sherpa_onnx` 2.0.0, which of open decoding, biased decoding (hotwords) and keyword spotting decides "did the child say this word" best, the spotter's threshold curve, load time and memory on this PC. The choice per language with its licence is written down.
2. **F7, the model registry.** One spec per course (files, sizes, SHA-256, source revision, licence). A file is hashed before it is loaded. An installer writes each file under a temporary name, checks size and SHA-256, and renames it only then; any mismatch deletes what was written. A model is loaded only when that language's voice switch is on (and the parent turned it on for a child who plays that course), off the main isolate. The download host stays unconfigured: the installer takes an injected fetcher, `lib/` holds no URL, and until the owner chooses R2 a model comes by `adb push` into the app's folder as the Hebrew model does.
3. **The per-word matcher.** One pure function from what the recogniser read (one or two readings) and the item's expected set (target, variants, foils, key words) to `confident`, `unsure` or `silence`. There is no "wrong" value. It has an accept threshold and a margin per language, a quiet fallback (more than 60% unsure in a visit switches the rest of the visit to echo, silently), and the false-confident gate.
4. **LS09 `say_it` 1.0.** Schema, model, validator rules, session and lesson wiring. The voice says the word with its picture, a pause, the voice again; with voice on the child taps the microphone and says it; confident gets "שָׁמַעְתִּי:" and the word, unsure gets "בּוֹאוּ נֹאמַר יַחַד." and the model of the word, at most one more try by a tap, never required; then a tap on the picture goes on. The mic opens only on a tap and only with the language's switch on. The same *say step* (controller and mic button) is reusable by LS10 and LS08 `echo` in L4. Speech evidence counts only for speaking (`spk`) skills of a language course and at most 50% of such a skill's successes; unsure writes nothing that reaches the engine.
5. **The release gate and the eval tooling.** A pure gate function (counts of foil readings and correct readings per language and age band, to pass, fail or "not enough readings") with its test, and `app/tool/asr_eval.dart` and `tools/run-asr-eval.ps1` taking a language, a mode (open, hotwords) and a speakers file, printing the confident rate, the false-confident rate and a threshold sweep.
6. Analyzer clean, format clean, the whole Flutter suite green, source-rule tests for the mic and the vocabulary, PLAN.md updated where the build differs.

| # | Decision | Why |
|---|---|---|
| D-1 | The result type of a word check has three members, `confident`, `unsure`, `silence`. No "wrong" exists in the type, and a source-rule test fails if the language speech code uses the wrong or correct vocabulary of the tap path. | Research 2.2, frame 5.1. |

## 4. The release gate per language

Per language, and per age band when the data has them (A 3 to 4, B 5 to 6, C 7 to 8): the course's say-it words and their foils, read by adults on the team and, live and supervised by the owner, by children; only counts are kept. It passes when at least 60 foil readings were made, at most 5% of them came out confident, and more than half of the correct readings came out confident. If it fails, that language's say-it ships in echo mode until a better model passes. The code that decides this is `release_gate.dart`; the tool prints its verdict from a labels file. English and Russian cannot be called passed by the numbers in this milestone: the public data are adults and single words only, and the children's data are the owner's to record (`docs/owner-todo.md` P6).

## 5. Security items (for the security-engineer's review)

1. **Rule 9.** No package; `network_hosts.json` unchanged; a test fails on a URL literal in `lib/`. The installer has no network code of its own.
2. **Model files are data parsed by native code.** Size and SHA-256 of every file are written in the app, checked before load, and again after any copy; a temporary name is renamed only after the check; a mismatch deletes the file.
3. **Rule 5 and child safety.** The recogniser's text is compared, never shown, logged, stored or sent. Only the enum outcome is kept. The mic opens on a tap, only with the language's switch on; audio lives in memory while the child speaks; no file, no network in the speech code (`source_rules` tests).
4. **Hotword strings** come from signed content only (target, variants, foils), never from a child, a name or a tutor line; the validator refuses the characters that change a hotword list (`:`, `#`, `@`, `/`, newline).
5. **A child's own name** is never a hotword (decision 10, frame 5.2).

### 7.2 Is a confidence available? Not through the Dart API, and it would add nothing

`OnlineRecognizerResult` carries `text`, `tokens` and `timestamps` only (`online_recognizer.dart` reads three keys of the JSON). The native JSON of 2.0.0 does contain `ys_probs` (one log-probability per token), in `greedy_search` and in `modified_beam_search`, with and without hotwords, for the Hebrew, English and Russian models (`context_scores` appears with hotwords, `lm_probs` is empty). It is reachable only through `package:sherpa_onnx/src/sherpa_onnx_bindings.dart`, which the package does not export: an implementation import, brittle, or a patched package. **It is not needed.** The same trials with a confidence gate (mean token probability of the reading at least 0.5, 0.7, 0.85) gave a recall of 0% at every gate for the biased reading, and 4% at 0.5 and 0% above for the open reading. The model's own token probabilities are low on isolated words even when the word is right, and under a boost they are not the boosted scores. So **no fork and no patch is requested.**

### 7.3 Open decoding, hotwords and keyword spotting for "did the child say this word"

Data: the public Speech Commands v0.02 test set (CC BY 4.0, `speech_commands_test_set_v0.02.tar.gz`; md5 `854c580ee90bff80c516491c84544e32` equals the published ETag; SHA-256): one-second recordings of single words by many speakers on their own microphones. Ten words (yes, no, up, down, left, right, on, off, stop, go), 12 clips each (120 clips, fixed seed). Per clip, trials of two kinds: a random option set of three that holds the word, and for eight words a minimal-pair set (go/no, on/off, up/down, left/right). A positive trial is the clip against its own word as target; a negative trial is the same clip against another option as target (the child "said a foil"). Also 36 clips of other words and background noise with nothing on screen said. Variants: clean, white noise at 10 dB, and a pitch raised 25% (an adult voice made higher, a smoke test, **not evidence about children**). The decision is the relative one of D-3 (text similarity of 0.75 or more, ahead of every foil by 0.15). Whole-stream decode on this PC (1 s word, 1 s lead silence, 1.5 s tail): open median 136 ms, biased 156 ms. The stream must be padded with silence before the word: with 0.3 s of lead the open reading found the word in 4% of clips, with 1 s in 17.5%.

| Mode (1 s lead, clean) | Recall, word said | False-confident, a foil said (far, minimal pair) | Nothing said |
|---|---|---|---|
| open, greedy | 17.5% (21/120) | 0/240, 0/192 | 0/36 |
| open, beam search | 35.8% | 0/240 | 0/36 |
| **hotwords, boost 8** | **82.5%** (99/120); minimal pair 81.3% | **0/240, 0/192** | **0/36** |
| hotwords, boost 12 | 83.3%; 81.3% | 0/240, 0/192 | 0/36 |
| hotwords, boost 16 | 80.8%; 80.2% | 0/240, 0/192 | 0/36 |
| hotwords and open reading must agree | 16.7% | 0 | 0 |
| keyword spotter, threshold 0.02 (0.3 s lead) | 55.8% | 0 | not run |

Biased decoding with the options as hotwords at one equal boost, then the relative decision, wins: recall 83% clean, 75% at pitch +25%, 59% at 10 dB noise, and no false-confident in any variant (the 95% upper bound for 0 of 240 is 1.25%). The boost curve is flat from 8 to 16 and falls below 8 (boost 3: 62%, boost 5: 72%). Requiring the open reading to agree destroys recall, so there is no agreement rule. **Keyword spotting loses.** Its threshold curve is monotone (0.02: 56%, 0.05: 49%, 0.1: 41%, 0.2: 33%, 0.45: 24%, 0.8: 10%; never a false alarm in these trials), it was worse with a longer lead (30% at 0.02), its licence is unknown, and the C API of 2.0.0 does not BPE-encode keywords for the spotter (`modelingUnit` and `bpeVocab` do not reach it), so the app would need its own tokeniser. **Hebrew:** with `modelingUnit: bpe` the Hebrew model's beam search printed Latin letters for audio that greedy search printed in Hebrew, so hotwords are not used for Hebrew; it keeps open decoding (optional practice, never evidence).

**Russian:** no public single-word Russian sample was reachable without an account or a licence (Common Voice needs one, the Lyakso child corpora need a request). On the model's own two test sentences (adult, read speech) open and biased decoding both read the words exactly: recall 80/80, false-confident 0/160 for words not in the sentence, and 0 of 270 readings of silence, white noise and the English sentence for each mode. That proves the mechanism and the normalisation, nothing about children or isolated words. Russian isolated-word accuracy stays open until the Russian list is read live.

### 7.5 What the spike decides

- **English:** the 20M zipformer, int8, biased decode with boost 8, 1 s of lead silence, the relative decision. Adults saying single words against three options: 83% recall and no false-confident. No child has been measured, and 59% at 10 dB shows what a noisy room costs. The design makes an unsure result harmless.
- **Russian:** the Vosk small streaming model with the same method; isolated words unmeasured. It ships in echo mode until the Russian list is read live and the gate passes.

## 10. After QA and the security review (2026-11-06)

QA-L3-1 to QA-L3-5 and SEC-L3-1 to SEC-L3-4 (item 2) are fixed; the QA proofs in `qa_l3_open_defects_test.dart` run in every build now.
- **QA-L3-1, the gate is enforced.** `SpeechModelSpec.released` is false for all three courses and `sayItReleasedProvider` reads it; `sayItAvailableProvider` needs it as well as the parent's switch and the model on the phone, so no language uses the microphone until the owner says it passed (one line in `model_spec.dart`). A test that wants the microphone overrides the provider (`AppRig.sayReleased`).
- **QA-L3-2 and SEC-L3-2.** `didChangeAppLifecycleState` stops the say step on any state but `resumed`; the listen is cancelled, the recorder closes, and what it heard is dropped.
- **QA-L3-3 and SEC-L3-1.** `Engine.apply` decides first for which skills a spoken answer counts: a success, without a hint, outside a probe, for a speaking skill, under the cap (speech successes at most the other hint-free successes; every spoken answer that is applied is such a success, so every one counts toward the cap).
